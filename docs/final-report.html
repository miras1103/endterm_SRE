Project Overview

The project implements a containerized web application using independent microservices, PostgreSQL, Docker Compose, Prometheus, Grafana, and Terraform. The system demonstrates infrastructure reproducibility, service isolation, monitoring, incident detection, incident mitigation, and postmortem analysis.

System Architecture

LayerComponentPurpose
FrontendNginx and JavaScript UIProvides login, product display, order creation, chat, and service status.
GatewayNginx reverse proxyRoutes requests to independent backend services.
BackendFastAPI microservicesAuthentication, users, products, orders, and chat.
DatabasePostgreSQLStores users, products, orders, and chat messages.
MonitoringPrometheus and GrafanaCollects metrics and visualizes service availability.
InfrastructureTerraform and AWS EC2Provisions a VM, network, security group, and public IP output.

Functional Requirements Implementation

Deployment Guide

Run the system on Windows with Docker Desktop and PowerShell.

docker compose up --build -d
docker compose ps

Open the application and tools:

  • Frontend: http://localhost
  • Gateway: http://localhost:8080
  • Prometheus: http://localhost:9090
  • Grafana: http://localhost:3000

Terraform Implementation

The Terraform configuration provisions an AWS VPC, public subnet, internet gateway, route table, security group, and EC2 instance. The security group opens SSH port 22, HTTP port 80, Grafana port 3000, and Prometheus port 9090. The output file returns the public IP address and service URLs.

cd terraform
terraform init
terraform plan
terraform apply

Incident Response Simulation

The simulated production incident affects the Order Service. The root cause is an invalid PostgreSQL hostname in the Order Service database connection string.

docker compose -f docker-compose.yml -f incident/docker-compose.incident.yml up -d order-service
docker compose logs order-service

Incident Report

ItemDetails
SummaryThe Order Service could not connect to PostgreSQL because its database hostname was changed to an invalid value.
ImpactUsers could view products and log in, but order creation failed. Chat and product retrieval remained available.
SeveritySEV-2 because a core business workflow was unavailable while the full platform was not completely down.
Root causeIncorrect Order Service environment variable: DATABASE_URL pointed to wrong-postgres-host.
MitigationThe environment variable was restored to postgres and the Order Service was restarted.
ResolutionHealth checks passed, order creation worked again, and Prometheus target status returned to healthy.

Postmortem Analysis

The incident was caused by a configuration error and was detected through service health checks, user-facing failure, container logs, and monitoring targets. The system had good fault isolation because product, authentication, user, and chat services remained available. The main weakness was that the invalid database configuration could reach runtime without earlier validation.

LessonAction Item
Configuration must be validated before deployment.Add startup validation and CI checks for required environment variables.
Order failures need direct alerting.Add Prometheus alert rules for Order Service downtime and high error rate.
Recovery should be documented.Keep a short runbook for logs, health checks, and service restart commands.
Deployments should reduce manual errors.Use environment templates and Terraform outputs during deployment.
